## Objectif

- Implémenter l'authentification backend avec Better Auth : signup, signin, signout, session cookie, route protégée, gestion des erreurs au format `{ code, message }`.
- Suivre le workflow test-first : inventaire → tests unitaires → scénarios de smoke → implémentation → vérification → code review → PR → merge.

## Tentatives échouées

- Le schéma Zod validait le format email AVANT de normaliser (trim + lowercase). Un email avec des espaces était refusé à tort. Corrigé en inversant l'ordre : `z.string().transform(normalizeEmail).pipe(z.email())`.
- Le status HTTP des erreurs mappées était codé en dur dans `authHandler.ts` avec un ternaire fragile (`mapped.code === 'EMAIL_ALREADY_EXISTS' ? 409 : 401`). Corrigé en faisant porter le `status` par l'objet retourné par `mapAuthError`.
- `normalizeEmail` était appelée deux fois (dans le schéma Zod et dans le hook `auth.ts`). Supprimé le doublon dans `auth.ts`.
- `requireAuth` renvoyait `{ error: 'Unauthorized' }` au lieu du format `{ code, message }` du reste de l'API. Corrigé.
- Les 4xx non mappés de Better Auth fuyaient bruts au client. Ajouté un fallback `BAD_REQUEST`.
